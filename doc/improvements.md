# AgentGauge 개선 방향 (UX · 디자인 · 기획 · 배포)

> 기준 버전: v0.3.1 · 작성일: 2026-08-13
> 코드·XAML·문자열 테이블·설치 스크립트·커밋 이력을 근거로 한 제안. 우선순위(P1 필수 / P2 권장 / P3 여유), 규모(S/M/L) 표기.
> 기존 v0.4 백로그(스파크라인, 컴팩트 모드, 트레이 퍼센트 아이콘, 적응형 갱신, 소진 예측 토스트, 고정 팝오버, ARM64)와 겹치는 항목은 재우선순위 관점으로만 언급.

## P1 — 필수 (신규 사용자 전환·신뢰에 직결)

### 1. 첫 실행 빈 화면에 행동 유도(CTA) 추가 — UX · S ✅ (2026-08-14 반영)
`UsageViewModel.Apply`는 스냅샷이 한 번도 없던 도구를 의도적으로 숨기므로, 아무 CLI에도 로그인하지 않은 신규 설치 사용자는 "아직 사용량이 없어요"(`Empty_NoHistory`)만 있는 빈 아크릴 패널을 보게 된다 (`ViewModels/UsageViewModel.cs:188-203`, `Views/PopoverWindow.xaml:186-195`). 해결책이 "설정 → 로그인"이라는 힌트가 전혀 없다.
**제안**: 빈 상태의 원인이 자격 증명 부재일 때 "로그인된 도구가 없어요" 메시지 + 인라인 **설정 열기** 버튼을 표시. 신규 사용자 전환에 가장 레버리지가 큰 단일 변경.

### 2. 트레이 우클릭 메뉴에 "열기" / "설정" 항목 추가 — UX · S
현재 컨텍스트 메뉴는 알림 토글 2종 + 시작 시 실행 + 종료뿐 (`Services/TrayIconService.cs:407-412`). 트레이 아이콘을 습관적으로 우클릭하는 사용자는 좌클릭이 팝오버를 연다는 사실을 발견할 수 없고, 메뉴에서 설정으로 가는 경로도 없다.
**제안**: 맨 위에 **"AgentGauge 열기"**(기본/굵게, 좌클릭과 동일 동작), 선택적으로 **"설정"** 항목 추가. AGENTS.md 메뉴 스펙과 충돌하지 않으나 반영 후 문서에 기록할 것.

### 3. PRIVACY.md 를 구현과 일치하도록 갱신 — 신뢰 · S ✅ (2026-08-14 반영)
정책 문서가 0.3의 측정 기반과 Copilot 도입 이전 상태에 머물러 있음:
- 3절: `api.github.com`이 "업데이트 확인 / 전송 데이터: 없음"으로 기재 — 실제로는 `GitHubCopilotProvider`가 사용자의 **GitHub OAuth 토큰**을 `copilot_internal/user`에 전송.
- 4절: `usage-history.db`(90일 샘플), `usage-cache.json`, `%APPDATA%\Gauge\logs\gauge.log`(진단 로그) 누락.
- 2절: Copilot 자격 증명 소스(`gh auth token`, `apps.json`/`hosts.json`) 누락.
"토큰을 읽지만 신뢰할 수 있다"가 제품의 핵심 약속인 무서명 앱에서 프라이버시 문서의 부정확성은 최악의 결함. 세 절 갱신 + 시행일 갱신.

### 4. 경고/위험 색상을 테마별 리소스로 이관 (라이트 테마 대비 실패 수정) — 디자인/접근성 · S ✅ (2026-08-14 반영)
`App.xaml:28-30`의 `UsageOkBrush #2E9E4F` / `UsageCautionBrush #FEAD0C` / `UsageDangerBrush #FE140C`는 단일 테마 하드코딩(주석으로 ThemeDictionaries 이관 예정 명시). 바 채움색으로는 무난하지만 `UsageCautionBrush`가 **텍스트**로도 쓰임 — "갱신 실패" 배지(`PopoverWindow.xaml:241-249`)와 페이스 경고 캡션. 라이트 아크릴 카드 위 #FEAD0C는 대비 약 1.6:1로 사실상 안 보임.
**제안**: 약속대로 `ThemeDictionaries` 이관, 라이트 테마용 진한 앰버/레드 텍스트 변형 정의. 앱 자체 규칙("색상만으로 상태 전달 금지")을 스스로 어기는 지점의 수정.

### 5. winget 매니페스트 제출 + README에 솔직한 SmartScreen 안내 — 배포 · S
코드 서명이 보류된 상태에서 `winget install`이 최선의 완화책: 신뢰 가능한 획득 경로 + 복붙 설치 명령 + 커뮤니티 저장소 검증. 설치기는 이미 winget 요건(무인 설치 `/VERYSILENT`, per-user, `PrivilegesRequired=lowest`)을 충족 (`installer/Gauge.iss`). `release.yml`에서 `wingetcreate update`로 자동화 가능.
README는 "무서명 **로컬 빌드**는 SmartScreen 경고 가능"(46행)이라 쓰지만 릴리스 빌드도 무서명(79행). "더 보기 → 실행" 안내와 winget 대안을 나란히 명시.

### 6. 트레이 퍼센트 텍스트 아이콘을 Phase 2 최우선으로 — 기획 · M (백로그 재우선순위)
현재 트레이 아이콘은 색상 변형 교체로만 상태 전달 (`TrayIconService.cs:49-57`). 16px에서 초록↔노랑 구분은 한눈에 안 되고 색각 이상 사용자에게 무용 — "팝오버를 열지 않고도 한눈에"라는 제품 약속(AGENTS.md UI rules)과 어긋남. 백로그의 퍼센트 텍스트 아이콘이 해답이며, 스파크라인보다 앞순위로 당길 것을 제안.

## P2 — 권장 (일상 사용 품질)

### 7. 사용량 화면에서 업데이트 가용성 노출 — UX · S
출시 확인 결과가 설정 푸터 버튼의 글리프 교체 + 툴팁으로만 표출 (`PopoverWindow.xaml:724-737`). 설정을 열지 않는 사용자는 새 버전을 영영 모름.
**제안**: 업데이트 가용 시 사용량 화면 톱니 버튼에 점 배지, 또는 푸터에 "업데이트 있음" 한 줄. "적용은 항상 의도적 클릭" 규칙은 유지.

### 8. 수동 새로고침 피드백 — UX · S
새로고침 버튼(`PopoverWindow.xaml:491-498`)은 진행 상태 표시가 없고, 10초 디바운스에 걸리면 클릭이 말 그대로 아무 일도 안 함.
**제안**: 강제 갱신 중 글리프 회전/비활성화, 디바운스로 스킵 시 `LastUpdatedText` 플래시로 클릭 인지시키기.

### 9. 임계값 토스트에 초기화 시각 포함 — UX · S
`Notif_ThresholdTitle`은 도구/윈도/퍼센트만 전달. "언제 돌아오나"가 자연스러운 다음 질문인데 팝오버를 열어야 알 수 있음. `ResetTimeFormatter` 출력이 이미 존재하므로 토스트 본문에 덧붙이기만 하면 됨. 백로그의 토스트 "열기" 버튼과 짝이 좋음.

### 10. 사용자가 직접 추가한 도구는 미로그인 상태도 카드로 표시 — UX · M
한 번도 성공하지 못한 도구는 메인 화면에서 숨겨지므로(`UsageViewModel.Apply` 주석 160-166행), 설정에서 Cursor를 추가해도 로그인 전엔 화면에 아무 변화가 없음. 로그인 필요 신호는 설정의 인증 카드에만 존재.
**제안**: 기본 등록(Claude/Codex)과 **사용자가 명시적으로 추가한** 도구를 구분해, 후자는 "로그인 필요" 슬림 카드 + 설정 이동(또는 CLI `LoginCommand` 직접 실행) 버튼으로 표시. 숨김의 원래 근거("미사용 기본 도구 카드 강요 금지")는 기본 등록에만 유지.

### 11. 바 모드 레이블 컬럼 정렬 — 디자인 · M
윈도 레이블 `MinWidth="44"`, 캡션 블록 고정 들여쓰기 `Margin="54,0,0,0"` (`PopoverWindow.xaml:287-293, 323-325`). 한국어 Copilot 레이블("코드 자동 완성", "프리미엄 요청")이나 영어 "Premium requests"는 44dip를 크게 초과 → 같은 카드 안에서 바 시작점이 들쭉날쭉.
**제안**: 카드 내 최장 레이블 폭 공유(shared size) 또는 초과 시 레이블-위-바 스택 레이아웃. 부수적으로 플랜 레이블 15px→12-13px 축소 검토(16px 도구명과 경쟁 중).

### 12. 퍼센트 숫자에 tabular figures 적용 — 디자인 · S
`PercentText`와 게이지 중앙 26pt 숫자가 갱신마다 폭이 변해 흔들림. Pretendard는 `tnum`을 지원하므로 해당 TextBlock에 tabular 숫자 적용으로 지터 제거. 작지만 매일 보이는 폴리시.

### 13. 스파크라인 — 생각보다 작음, Phase 2 선두로 — 기획 · M (백로그 재우선순위)
90일치 샘플이 DB에 있는데 UI에 드러나는 건 ETA 캡션 한 줄뿐. 배관은 이미 UI 스레드 안전(`IUsageHistorySource.GetRecent`는 메모리 미러, `ToolCardViewModel.cs:124-130`에서 이미 행마다 호출 중). 24시간 미니 스파크라인은 같은 호출의 룩백만 늘리면 됨 — 신규 서비스/스토어 불필요. 트레이 퍼센트 아이콘과 함께 Phase 2 선두 제안.

### 14. 도구별 "숨기기/폴링 일시정지" — 기획 · S/M
지금 도구를 조용히 시키는 유일한 방법은 등록·알림 이력까지 버리는 "연결 해제"뿐. 일주일간 Cursor를 안 쓰는 사용자는 죽은 카드를 보거나 등록을 잃어야 함.
**제안**: 인증 카드에 카드 숨김/폴링 정지 토글. 도구×종류 알림 매트릭스 금지 결정과 무관(가시성 설정이지 알림 설정이 아님).

### 15. 카피 정리 (en/ja) — 로컬라이제이션 · S
- `Auth_Missing` en: "Sign in to see **more accurate** usage" — 로그인 없이는 아무것도 안 보이므로 과장. ko와 같게 "Sign in to see usage"로 (`Strings.cs:129-131`).
- `Tray_NoData` en: "{0} no data" → "{0}: no data" (`Strings.cs:62`).

### 16. README에 프라이버시 링크·데이터 위치·제거 안내 — 배포 · S
README가 PRIVACY.md를 한 번도 참조하지 않음. 데이터 위치(`%APPDATA%\Gauge`)와 제거 시 잔존물(설치기는 Run 키만 삭제, `Gauge.iss:73-77` — `%APPDATA%\Gauge`는 남음) 명시.

### 17. 설치기 메타데이터 — 배포 · S
`Gauge.iss`에 `AppPublisherURL`/`AppSupportURL`/`AppUpdatesURL` 미설정. 셋 다 GitHub 저장소로 지정하면 앱 목록 항목이 익명이 아닌 관리되는 소프트웨어로 보임 — 무서명 앱이 공짜로 얻는 몇 안 되는 신뢰 신호.

## P3 — 여유 (완성도)

### 18. 절대 초기화 시각 툴팁 — UX · S
5시간 윈도는 상대 시각("2시간 13분 후 초기화")만 표시. 세션을 계획하는 파워 유저를 위해 "… (14:30)" 형식 병기 또는 툴팁. 언어당 포맷 문자열 1개 비용.

### 19. 카드 "텍스트로 복사" / CSV 내보내기 — 기획 · S
카드 우클릭 → "Claude Code — 5h 63%, weekly 41%, resets …" 복사(팀 채팅 공유용), 설정에서 `usage-history.db` CSV 내보내기. 이 앱의 사용자층에 정확히 맞는 저비용 기능. 사용자 주도 로컬 내보내기라 프라이버시 변화 없음.

### 20. 게이지 모드 패밀리 레이블 중복 축소 — 디자인 · S (의도된 선택 재고)
게이지 모드는 같은 패밀리 행 안에서도 게이지마다 `FamilyLabel` 반복 — Antigravity 4개 윈도면 "Gemini Gemini Claude/GPT Claude/GPT". 구분선+행 그루핑이 이미 패밀리를 나누므로 바 모드처럼 행당 1회 표기 검토.

### 21. en/ja 토스트 의미 불일치 — 로컬라이제이션 · S
ja `Notif_ThresholdTitle` "上限{2}%に到達"(도달)는 70%에서 어색 — en "used"에 맞춰 "上限{2}%を使用"으로. scoped 변형도 동일. `Label_BillingCycle` "Usage/사용량"은 정보가 없는 레이블 — Cursor 카드에서 "결제 주기/Cycle/サイクル"로.

### 22. 저장소 표면 정리 — 배포 · S
GitHub topics(winui3, system-tray, claude-code, …), 소셜 프리뷰 이미지(배너 기존재), 릴리스 노트 상단 ko/en 요약 고정. 멀티 계정 미지원은 README "Current limitations"에 한 줄 명시.
